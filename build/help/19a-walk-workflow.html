Run the same steps for several families, with a workflow

When you do the same job for one family after another, such as making the GA4GH files from each drawing, checking them and de-identifying them, a workflow does all the steps in one go. In this walkthrough you run an example for two families, make a workflow that weighs up a family's mode of inheritance from its drawing, and make another from tools you've run one at a time.

1 · Run an example

The example Share a drawing in the GA4GH standard does what Share a family's pedigree in the GA4GH standard does by hand. It makes a GA4GH Pedigree and a Phenopackets Family from a drawing, checks both, de-identifies the Family, then checks that too. It has two input files: the drawing, which is the Okafor family's to begin with, and a terms file for the conditions, which is the examples' terms file. Press Run.

The steps run one after another, and each says what it did: Wrote 2 files, or for a check, Valid: a correct GA4GH Pedigree. Open What it did under a step to see what the program printed, the files it wrote, with buttons to open or check them, and its command. The files are all in one folder, ~/results/share-a-drawing-in-the-ga4gh-standard/okafor, with the record of the run, workflow-run.json, and its commands, commands.sh.

2 · Run it for another family

Now run it for the Lynch family. Choose lynch.studio.json as the drawing (the button below does this for you), and leave the terms file as it is, because it has terms for the Lynch family's conditions too. This run's files go in a folder of their own, …/lynch, beside the Okafor family's.

The Workflows page lists both runs under Runs, and View shows either of them again. For a drawing of your own, choose it instead. If the examples' terms file doesn't have its conditions, make a terms file for them first with Match conditions to terms, and choose that file as well.

3 · Make a workflow of your own

This workflow makes a PED file from a drawing, then weighs up the family's mode of inheritance from it with PedNet.

  1. On the Workflows page, press New workflow. The editor opens, on an empty workflow.
  2. Press + Input file. The box it adds takes a Pedigree Studio drawing, which is what this workflow needs. If you click the box, you can give it a name, such as The drawing, or choose another kind of file.
  3. Press the + by Pedigree Studio drawing, on the right of the box. It lists the tools that read a drawing: choose Drawing → PED or MPED. Its box appears to the right, already reading the drawing.
  4. Press the + by PED or MPED file, on the new box, and choose Mode of inheritance.
  5. Click the background. Under Checks, it says Ready to run. Give the workflow a name at the top, such as Drawing to mode of inheritance, and a description under What it does.

Instead of using the +, you can add each step with + Add a step, then drag from the dot by PED or MPED file to the input of Mode of inheritance. Either way, the editor saves the workflow as you go, in ~/workflows.

Press Run, choose lynch.studio.json as the input file, and press Run again. The last step says Family FAM1: autosomal dominant, and under it are PedNet's probabilities for each mode of inheritance. Weigh up the mode of inheritance, and rank candidate variants explains them.

4 · Make one from tools you've run

If you've already done a job once, tool by tool, the Workflows page can turn what you did into a workflow.

  1. Make the GA4GH files from the Price family's drawing: the button below opens Drawing → GA4GH Pedigree and Phenopackets with the drawing and the terms file filled in. Press Run.
  2. Under the result, press Check beside the GA4GH Pedigree, then Run.
  3. Open the Workflows page, and press Make one from the tools you've run. The two tools you've just run are ticked. Untick any others, give the workflow a name, and press Make the workflow.

The workflow opens in the editor. The drawing and the terms file are its inputs, and the Check reads the GA4GH Pedigree that the first step writes, as it did when you ran the tools. Run it for any other drawing, as you did in step 2.

The same in the terminal

Each run's commands.sh holds the commands its steps ran. This runs the steps of the Lynch family's run again:

bash ~/results/share-a-drawing-in-the-ga4gh-standard/lynch/commands.sh
