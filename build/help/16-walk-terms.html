Give the conditions ontology terms

GA4GH and Phenopackets files name each condition by a term from an ontology, so that software and people everywhere read it in the same way. A disease is named by a term from the Mondo Disease Ontology, and a sign or symptom by a term from the Human Phenotype Ontology (HPO). This walkthrough finds the terms for a drawing's conditions, and fills in the terms that an existing file lacks.

For a drawing: Match conditions to terms

1 · Choose the drawing

The tool lists the conditions in the drawing's colour key, with the number of people who have each one. If you keep a terms file for a project, start from it. Conditions it already has are filled in, and your new matches are added to it.

2 · Choose where to search

  • EBI's Ontology Lookup Service searches the latest releases, and finds terms that a local search can miss. It needs the internet, and it sends EBI the words you search for. That's the condition's name, not the drawing.
  • Copies of the ontologies on this computer work without the internet and send nothing. You can download the HPO, which is about 11 MB, from the tool into ~/ontologies. Mondo's file is about 50 MB, and its host doesn't let web pages download it. Instead, download mondo.obo with your browser from Mondo's download page, then add it with From my computer…. The first search of a file reads all of it, which takes several seconds.

3 · Match each condition

For each condition, say whether it's a disease (Mondo) or a sign or symptom (HPO). The tool makes a first guess from the name. Then press Suggest. Each suggestion shows the term's id and label, whether its label or a synonym matched, a score and the term's definition. Choose the one that's right. If none is, change the words and search again. If you already know the id, type it and press Use this id. The tool looks it up, so that its label and release are recorded.

Choosing a term

Choose the most specific term that's true of everyone with the condition in this family. Hearing impairment (HP:0000365) is true of the Okafor twins. If their hearing loss is known to be sensorineural, Congenital sensorineural hearing impairment (HP:0008527) says more. Use a Mondo term when there's a diagnosis, and HPO terms for features without one. Read the definition, because two terms can share a name, as breast cancer (MONDO:0007254) and breast carcinoma (MONDO:0004989) nearly do.

4 · Keep the matches

Save writes the terms file, which for the Price family is ~/terms/price-terms.json. Tick Also write the ids into the drawing's colour key to make a copy of the drawing whose key reads Breast cancer [MONDO:0007254]. A drawing like that carries its terms wherever it goes, and converts without a terms file. Then Next opens Drawing → GA4GH with the drawing and the terms file already chosen.

For a GA4GH file: Fill in missing terms

Files from older tools, or from elsewhere, may name conditions without their ids. Fill in missing terms gives each one its id from a terms file, ignoring case when it matches the names. It can also look up names that aren't in the terms file. It uses a term it finds when the term's name, or one of its synonyms, is the same as the condition's name, whatever the case and punctuation. With a lower threshold it takes close matches too, but each of those is a guess for you to check. It writes a log of what it decided next to the new file, ….normalised.log.json.

A file made by an older tool must be upgraded first, and the tool tells you when that's needed. To try this, upgrade the older example, then fill in its terms from the examples' terms file. The tool picks your newest file, which is the upgraded one.

A terms file

A terms file is a small JSON file. It lists each condition's name in the drawing, with its term and the release of the ontology the term came from. You can also write one by hand, and an id on its own is enough.

{
  "Breast cancer": {"id": "MONDO:0007254", "label": "breast cancer", "version": "2026-10-06"},
  "Hearing loss from birth": {"id": "HP:0000365", "label": "Hearing impairment", "version": "2026-09-01"},
  "Ovarian cancer": "MONDO:0008170"
}

One terms file can serve many drawings, and the names are matched whatever their case. Ontology terms and terms files has more.

The same in the terminal and in Python

There's no command that reads a drawing's colour key and lets you work through each condition with the mouse. That's what the tool is for. These commands use a terms file:

studio2ga4gh /data/examples/price.studio.json -t /data/examples/example-terms.json -d ~/results
pedigree-ga4gh upgrade /data/examples/older/studio2ga4gh-0.3_phenopackets-family.json -o ~/results/older_phenopackets-family.json
phenotk normalise ~/results/older_phenopackets-family.json --mapping /data/examples/example-terms.json --no-online -o ~/results/older.normalised.json

hponorm and mondonorm, the programs behind the searches, match the names in a GA4GH or Phenopackets file by asking you about each one as they go. This terminal can't answer their questions, so here they stop at the first one. They can take their answers from a file instead: hponorm FILE.json --mapping answers.json --auto-remembered -o OUT.json. In Python, their searches look like this:

from hponorm.ols import OlsClient            # EBI's Ontology Lookup Service (online)
for c in OlsClient().search("hearing loss from birth", limit=5):
    print(c.id, c.label, c.score)

from mondonorm.mondo import MondoIndex      # a copy of Mondo on this computer
index = MondoIndex.load("/home/user/ontologies/mondo.obo", allow_download=False)
for c in index.search("breast cancer", limit=5):
    print(c.id, c.label, c.score)
