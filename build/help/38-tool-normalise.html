Fill in missing terms

This tool gives an ontology id to every disease and phenotype in a GA4GH or Phenopackets file that has a name but no id. It takes the id from a terms file, or looks the name up. It also writes the file in the standard form, with the ontology resources that its terms need.

The form

The file
Choose a GA4GH Pedigree, or a Phenopackets Family, Cohort or Phenopacket. A file from an older tool must be upgraded first.
Terms file
Choose a file of names and their terms (terms files). Upper and lower case don't matter when the names are matched. The releases in the terms file are recorded in the file's resources.
Look up names without a term
Choose No to use only the terms file, or look names up on EBI's Ontology Lookup Service, which is online, or in copies of the ontologies on this computer. For the copies, choose hp.obo and mondo.obo.
Accept a looked-up match from
This is the lowest score, from 0.5 to 1, at which a term the tool finds is used. A term's own name scores 1 and one of its synonyms 0.98, whatever the case and punctuation, and any other name scores less. So the default, 0.98, only accepts a term whose own name or synonym is the condition's name. If a name's best match is less close than that, it's left without a term and listed. Entries in a terms file are always used.
Save as
The new file is saved as ~/results/name.normalised.json. A log of every decision goes next to it, as ….normalised.log.json.

By default, the tool doesn't guess. If neither the terms file nor a look-up finds a term for a name, its id stays empty and the summary lists it. You can lower the threshold to accept close matches as well, but each of those is a guess, and the log asks you to check it. Names that are spelt almost alike can mean opposite things. For example, Maternal hypothyroidism is not Maternal hyperthyroidism. Look at the log before you rely on a looked-up match.

Each term goes where its kind belongs. Older tools wrote every condition as a disease, so a “disease” that's given an HPO term, such as Hearing loss from birth (HP:0000365), moves to the phenotypic features. In the same way, a phenotype that's given a Mondo term moves to the diseases. The summary notes each move.

In the terminal

pedigree-ga4gh upgrade /data/examples/older/studio2ga4gh-0.3_phenopackets-family.json -o ~/results/older.json
phenotk normalise ~/results/older.json --mapping /data/examples/example-terms.json --no-online --log ~/results/older.log.json -o ~/results/older.normalised.json
pedigree-ga4gh validate ~/results/older.normalised.json
Option
--mapping FILEa terms file, or the log of an earlier run
--no-onlineuse the terms file only, with no look-ups
--backend ols|local, --hpo-file, --mondo-file, --thresholdwhere to look names up, and the lowest score to accept (by default 0.98, which means the term's own name or a synonym)
--terms-only, --structure-onlyonly fill in terms, or only tidy the structure
--log FILE, -o FILE, --in-placewhere the log and the new file go

In Python

import json
import phenopacket_toolkit as ptk
from phenopacket_toolkit.ops import normalise

doc = ptk.read("/home/user/results/older.json")
mapping = json.load(open("/data/examples/example-terms.json"))
new, log = normalise(doc, mapping=mapping, use_ontology=False)
ptk.write(new, "/home/user/results/older.normalised.json")
print(log.summary())
