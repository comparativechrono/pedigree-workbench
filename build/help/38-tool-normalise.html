Fill in missing terms

Gives an ontology id to every disease and phenotype in a GA4GH or Phenopackets file that has a name but no id, from a terms file or by looking the name up. It also writes the file in the standard form, with the ontology resources its terms need.

The form

The file
A GA4GH Pedigree, a Phenopackets Family, Cohort or Phenopacket. A file from an older tool must be upgraded first.
Terms file
Names and their terms (terms files). The names are matched without regard to case, and the terms file's releases are recorded in the file's resources.
Look up names without a term
No (the terms file only), or on EBI's Ontology Lookup Service (online), or in copies of the ontologies on this computer (choose hp.obo and mondo.obo).
Accept a looked-up match from
How close the best match must be, from 0.5 to 1 (1 is exact). A name whose best match is less close is left without a term, and listed. A terms file's entries are always used.
Save as
~/results/name.normalised.json, with a log of every decision beside it, ….normalised.log.json.

Nothing is guessed: a name that neither the terms file nor a close enough match gives a term keeps its empty id, and the summary lists it. Look at the log before you rely on a looked-up match.

A term goes where its kind belongs: older tools wrote every condition as a disease, so a “disease” that is given an HPO term (Hearing loss from birth, HP:0000365) moves to the phenotypic features, and a phenotype given a Mondo term moves to the diseases. The summary notes each move.

In the terminal

pedigree-ga4gh upgrade /data/examples/older/studio2ga4gh-0.3_phenopackets-family.json -o ~/results/older.json
phenotk normalise ~/results/older.json --mapping /data/examples/example-terms.json --no-online --log ~/results/older.log.json -o ~/results/older.normalised.json
pedigree-ga4gh validate ~/results/older.normalised.json
Option
--mapping FILEa terms file, or the log of an earlier run
--no-onlinethe terms file only: no look-ups
--backend ols|local, --hpo-file, --mondo-file, --thresholdwhere to look names up, and how close a match must be
--terms-only, --structure-onlyonly fill in terms, or only tidy the structure
--log FILE, -o FILE, --in-placewhere the log and the new file go

In Python

import json
import phenopacket_toolkit as ptk
from phenopacket_toolkit.ops import normalise

doc = ptk.read("/home/user/results/older.json")
mapping = json.load(open("/data/examples/example-terms.json"))
new, log = normalise(doc, mapping=mapping, use_ontology=False)
ptk.write(new, "/home/user/results/older.normalised.json")
print(log.summary())
