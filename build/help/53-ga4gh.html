The GA4GH Pedigree

The Global Alliance for Genomics and Health (GA4GH) is writing a standard for pedigrees. This page says what that standard is so far, the form in which the workbench writes a GA4GH Pedigree, why, and what was wrong with the files our older tools wrote.

The standard, so far

The GA4GH Pedigree Standard is still in development. Its documentation describes a conceptual model: a pedigree is a set of individuals and the relationships between them, each relationship named with a term of the Kinship Ontology, KIN. It is not a file format of its own. It is carried by other standards, in two forms:

  • In Phenopackets. A new message, a Pedigree with its individuals as Phenopackets and its relationships named by KIN terms, was proposed for the Phenopackets schema in November 2022. The proposal was closed without being merged in September 2025, because the pedigree group had not yet decided. It is in no release of Phenopackets.
  • In HL7 FHIR, with a draft implementation guide.

Neither form is approved yet. The approved GA4GH format that the workbench writes is Phenopackets version 2: the Phenopackets Family, and the Phenopackets inside the GA4GH Pedigree.

The form the workbench writes

A GA4GH Pedigree from the workbench is the Phenopackets form of the proposal, written as Phenopackets' JSON is written (field names in camelCase):

{
  "id": "FAM1",
  "narrative": "Pedigree drawn in Pedigree Studio: 16 people; proband IV-3. …",
  "date": "2026-10-17",
  "indexPatients": ["IV-3"],
  "individuals": [
    {
      "id": "FAM1-II-3",
      "subject": {"id": "II-3", "vitalStatus": {"status": "ALIVE"}, "sex": "FEMALE"},
      "diseases": [{"term": {"id": "MONDO:0007254", "label": "breast cancer"}}],
      "metaData": {
        "created": "2026-10-17T09:00:00Z", "createdBy": "studio2ga4gh 0.4.0",
        "resources": [{"id": "mondo", "name": "Mondo Disease Ontology", "version": "2026-10-06",
                       "namespacePrefix": "MONDO", "iriPrefix": "http://purl.obolibrary.org/obo/MONDO_", …}],
        "phenopacketSchemaVersion": "2.0"
      }
    },
    …
  ],
  "relationships": [
    {"individualId": "I-1", "relation": {"id": "KIN:028", "label": "isBiologicalFatherOf"}, "relativeId": "II-3"},
    …
  ]
}
  • Every individual is a complete Phenopacket version 2, with its own metaData, so that everything about a person – sex, whether they are alive, diseases, phenotypes – is in an approved, checked structure. Only the wrapper, the list of individuals and the relationships, comes from the proposal.
  • Each relationship is one current KIN term, written once (a symmetric one, such as partners or twins, in one direction). KIN lists them.
  • People are named by their pedigree numbers (II-3) unless you choose otherwise. Names are never written: Phenopackets have no field for a name.
  • A condition with no ontology term is left out, with a note, because a disease or phenotype without an id is invalid.
  • What the standard has no field for – a carrier, a pregnancy, a symbol that stands for several people – goes into the narrative, so that it is not lost.

Why this form

  • The Phenopackets Family that goes with it is Phenopackets version 2 already, and the phenopacket toolkit is built around Phenopackets: one model throughout.
  • With each individual a Phenopacket, all that is said about a person can be checked against an approved schema, as the GA4GH's own validator checks it.
  • The standard's own examples use this form.

If the GA4GH settles on a different form, one module of the workbench's packages (pedigree_ga4gh) changes, and the upgrade rewrites files from this form.

One implementation

All of the workbench's tools read and write GA4GH files through one package, pedigree-ga4gh: studio2ga4gh, ga4gh2studio and the phenopacket toolkit can no longer disagree about the form. Its check applies the rules of the Phenopackets schema and of phenopacket-tools, the GA4GH's validator, and those of the pedigree (Check against the standard).

What was wrong with the older files

Before, studio2ga4gh and abusua2ga4gh each wrote GA4GH files their own way, and the phenopacket toolkit had a “dialect” for reading each. Neither way was correct:

abusua2ga4gh 0.2, KINKIN:039 for a sperm donor; KIN:011 with another label; foster and social parents as adoptive parents (KIN:022)KIN:039 is hasGestationalCarrier, and a sperm donor is KIN:004; KIN calls KIN:011 isPolyzygoticMultipleBirthSiblingOf; KIN has KIN:021 isFosterParentOf and KIN:020 isParentFigureOf

Files in the older forms are recognised, and Upgrade a file from an older tool rewrites them once, in the standard form.

Two things that are not errors

A Family may leave out consanguinousParents when it is false (the workbench writes it always), and an empty list of resources is not itself wrong: proto3 JSON may leave out default values, and phenopacket-tools accepts either. What is required is a resource for every ontology prefix that the terms use. (The field is spelt consanguinous, as the schema spells it.)
