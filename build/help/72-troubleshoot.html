When something goes wrong

The common problems, and what to do about each.

Python does not start
Python is downloaded from cdn.jsdelivr.net the first time (about 10 MB). If the network blocks that site, or there is no connection, the tools, the notebook and the programs cannot run; the Studio and the Files tab still work. Try again on another network. After the first time, the browser usually keeps a copy.
“This GA4GH Pedigree was written by studio2ga4gh 0.3 or earlier …”
The file is in an older form, which the tools no longer read. Upgrade a file from an older tool rewrites it, once.
A condition is missing from the GA4GH files
It has no ontology term, so it was left out (the tool said so under its result). Give it a term with Match conditions to terms, and convert again with the terms file. Check that the name in the terms file is the name in the colour key; case does not matter, spelling does.
A colour is not counted as a condition
The colour key does not name it. Open the drawing in the Studio, click the key and type the condition's name beside that colour.
“EBI's Ontology Lookup Service did not answer”
The service is down or slow, or the network blocks www.ebi.ac.uk. Try again later, or search copies of the ontologies on this computer instead (2 · Search in).
The PED file has names as ids, or the same id twice
studio2ped uses the text under the symbols as ids. Change the labels in the drawing, or make the PED file through the GA4GH files, which use pedigree numbers (Make a PED file for a linkage program).
The drawing a tool made looks untidy
Press Tidy in the Studio tab, or tick Lay it out afresh with Pedigree Studio's Tidy before running the tool.
The Studio tab shows the wrong drawing, or none
The bar above it says which file the drawing on show belongs to. Open… shows any of your drawings; the file button lists the latest.
A tool waits for a long time
A notebook cell may be running: the tools share the notebook's Python, and wait for the cell to finish (stop it in the Notebook tab). The first search of a local copy of Mondo also takes a while: it reads the whole file.
hponorm or mondonorm stops at once in the terminal
They ask questions that this terminal cannot answer. Give them the answers in a file, or use Fill in missing terms or Match conditions to terms (The Terminal).
My files have gone
Are you in the same browser, on the same computer, and not in a private window? The files are kept by the browser for this site only. A browser that clears site data when it closes deletes them too: download what you want to keep.
“The workbench is open in another tab or window too”
Both tabs keep files in the same place, and one can overwrite what the other saved. Close one of them.

Reporting a fault

If a tool fails with Python's traceback (under the result: Python's traceback), or a file the workbench made does not pass its own check, that is a fault. Report it on the workbench's issues page, with the traceback and, if you can, a file that shows it – an example, or a de-identified copy of yours. Never attach a family's real data.
