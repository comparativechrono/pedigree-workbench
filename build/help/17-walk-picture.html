Turn a picture of a pedigree into a PED file and a drawing

A pedigree in a paper, a clinic letter or an old scan, or one sketched in a hurry, is only a picture. PedInterp reads one into a PED file, which the other tools can use, and into a Pedigree Studio drawing laid out as the picture is, where you can check it against the picture and add what a PED file can't hold. The example is a picture of the Lynch family, drawn as pedigrees are drawn in papers.

1 · Add the picture

Add your picture with From my computer… under the file box of the tool in the next step, or with My files → Add files from my computer… at the top right. A PNG file is best. A scan or a screenshot reads better than a photograph of a page, because the drawing needs to be dark on white, sharp, and square to the edges. A pedigree sketched by hand, with Pedigree Studio's Draw tool or on paper, can be read too: tick Drawn by hand in the next step.

2 · Read it

Picture → PED file and drawing finds the symbols and the lines, works out who is whose parent, and writes the PED file and the drawing. The people are numbered by generation, from the top, and from the left in each generation: I-1, I-2, II-1 and so on. The first time, Python downloads what PedInterp needs, about 21 MB, which takes a little while.

3 · Check it

The table under the result is the PED file's. It has a row for each person, with their parents (0 when they aren't in the picture), their sex (1 male, 2 female, 0 unknown), and whether they're affected (2) or not (1). A line under it says how many times PedInterp enlarged the picture to read it, which it chose to suit the symbols' size, and a warning follows if it thinks a line between the symbols was missed. Compare what it read with the picture: the drawing, in the next step, is the easiest way. If someone is missing or has the wrong parents, When something goes wrong says what to try.

The Lynch family's PED file in the examples was made from the drawing that the picture shows, so here the two files can be compared as well: the commands at the foot of this page do it.

4 · Open the drawing

Under the result, Open the drawing in Studio opens the drawing PedInterp made, ~/results/lynch.studio.json, in the Studio tab. It is laid out as the picture is, a row of symbols to a generation, so it is easy to set beside the picture. It has the twins, if there are any, and any couples who have no children, which a PED file can't hold. The Studio's Tidy lays it out afresh, if you'd rather.

In the Studio, put right anything misread, and add what the picture shows but PedInterp doesn't read, such as who has died (in the Lynch picture, I-1, I-2, II-2 and III-2) and the proband. Name the condition in the colour key, or give it in the tool's form before you read the picture, and the key names it with its ontology term. Then save the drawing. If you put anything right, make the PED file again from the drawing with Drawing → PED or MPED. From the drawing you can make the GA4GH files too, or look at the family with PedNet (Weigh up the mode of inheritance, and rank candidate variants).

If you untick Make a Pedigree Studio drawing too, the button under the result is Draw it instead, which makes a drawing laid out afresh: from the PED file (PED or MPED → drawing), or from the GA4GH Pedigree, if you ticked Write a GA4GH Pedigree too, which holds the twins as the drawing does.

The same in the terminal

pedinterp /data/examples/lynch.png --labels none --studio -q -d ~/results
diff <(cut -f2- ~/results/lynch.ped) <(cut -f2- /data/examples/lynch.ped) && echo "the same people, parents, sexes and status"
studio ~/results/lynch.studio.json

cut -f2- leaves out the family's id, which the two files give differently.
