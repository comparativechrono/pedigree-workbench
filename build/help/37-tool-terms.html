Match conditions to terms

This tool finds the ontology term for each condition in a drawing's colour key: a Mondo term for a disease, or an HPO term for a sign or symptom. It keeps your choices in a terms file, which Drawing → GA4GH reads. It uses the same searches as hponorm and mondonorm.

On the page

1 · The drawing
The drawing's conditions are listed under 3, with the number of people who have each one. Start from a terms file fills in the conditions that the terms file already has, and the matches you make are added to it when you save.
2 · Search in
Choose EBI's Ontology Lookup Service, which is online and has the latest releases, or copies of the ontologies on this computer, which work offline. For the copies, choose hp.obo and mondo.obo from your files. You can download the HPO from here into ~/ontologies. For Mondo, download its file with your browser from Mondo's download page, then add it with From my computer….
3 · The conditions
Each condition has a choice of a disease (Mondo) or a sign or symptom (HPO), the words to search for, and a Suggest button. The tool guesses which kind it is from the name, so check it. You get up to six suggestions, each with its id and label, a score out of 100 for how well it matches, and the definition. Each also says what your words matched: the term's label, or one of its synonyms. Choose one, or type an id and press Use this id. Suggest terms for all searches for every condition that hasn't been matched yet.
4 · Keep the matches
Save writes the terms file, ~/terms/drawing-terms.json. If you tick Also write the ids into the drawing's colour key, it also writes a copy of the drawing, ~/pedigrees/drawing-with-terms.studio.json. In the copy, the key has entries such as Breast cancer [MONDO:0007254]. Next opens Drawing → GA4GH with the drawing and the terms file already chosen.

What is sent where

If you use EBI's service, the words you search for and the ids you type are sent to EBI (www.ebi.ac.uk). Nothing else is sent, not even the drawing. If you use copies on this computer, nothing is sent anywhere. Downloading the HPO here fetches hp.obo from the HPO's repository on GitHub.

Good to know

  • The first search of a local file reads the whole file, which takes a few seconds for the HPO and longer for Mondo. The local search can miss terms that EBI's service would find, so if the term you expect is missing, try other words.
  • Each term's release is recorded with it in the terms file, and goes into the GA4GH files' metaData. That way, anyone can tell which version of the ontology the term came from.
  • If you type an id, the tool looks it up if it can. If it can't, because there's no copy of that ontology here or EBI doesn't answer, the id is used as you typed it. It's labelled with the condition's name, and the release is left out.
  • If the key itself already has an id, as in Condition X [MONDO:0009061], that condition counts as matched.

Give the conditions ontology terms walks you through it, with advice on choosing a term.

In Python

There's no command for this page. hponorm and mondonorm work on GA4GH and Phenopackets files, and ask about each name as they go. You can't answer their questions in the terminal, so there they take their answers from a file. You can use their searches in a notebook:

from hponorm.hpo import HpoIndex            # a copy of the HPO on this computer
index = HpoIndex.load("/home/user/ontologies/hp.obo", allow_download=False)
for c in index.search("hearing loss from birth", limit=6):
    print(c.id, c.label, c.score)
