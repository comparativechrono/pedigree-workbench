Check against the standard

Checks a GA4GH Pedigree, a Phenopackets Family, Cohort or Phenopacket, and says for each problem what it is, where it is in the file, and how to fix it. It needs nothing but the file: no Java, no internet.

What is checked

As phenopacket-tools does

phenopacket-tools is the validator for Phenopackets written by the team behind the Phenopackets schema. The check applies its rules:

  • The Phenopackets version 2 schema: the fields each part may have and must have, their types, the allowed values (sex, vital status, progress status …), the groups of which exactly one must be given, and minimum lengths and counts. A field the schema does not have is an error, because Phenopackets readers reject it.
  • The ontologies: every term's id is a CURIE (PREFIX:ID), and every prefix used is declared among the resources in the file's metaData, with all six of the resource's fields filled in. phenopacket-tools reads an empty field as a missing one.
  • Values: ages are ISO 8601 durations (P45Y), dates and times are in the right form.

And for a GA4GH Pedigree

  • Every id in the relationships and the index patients is the subject of one of the individuals, and no two individuals share an id.
  • Every relation is a current KIN term, written with KIN's own label; retired codes from earlier drafts of KIN are reported.
  • No one is related to themselves; a biological mother is female and a father male; no one has more than two genetic parents; no one is their own ancestor.

And for a Family

  • Everyone with a Phenopacket – the proband and the relatives – is in the pedigree, and no one is in it twice or has two Phenopackets.
  • Every father and mother in the pedigree is a person in it; a father is not recorded as female, nor a mother as male; no one is both someone's father and their mother; no one is their own ancestor.
  • No one's id is 0, which a PED file uses for “no parent”: their children would read as having none.

And one mistake of older files

  • HP:0032500 used for a carrier. It is valid in form – a real HPO term – but it is Exacerbated by tobacco use.

The check does not look terms up, so it cannot tell whether a term is the right one for the person: only that it is well formed and declared.

The result

Valid or Not valid, then a line for each finding: errors (the file is invalid), warnings (allowed, but probably a mistake), and notes (for information). Each has a code, such as empty-term-id, the place in the file, and how to fix it. A file from an older tool is recognised as such, with a button to upgrade it. Check a GA4GH file, or update an old one lists the commonest findings and their fixes.

In the terminal

pedigree-ga4gh validate /data/examples/okafor_phenopackets-family.json
pedigree-ga4gh validate --json /data/examples/older/abusua2ga4gh-0.2_phenopackets-family.json | head -20

The exit status is 0 for a valid file and 1 for an invalid one. --json prints the findings as JSON. phenotk validate FILE runs the same checks on a file in the standard form; a file from an older tool it refuses, with a message saying to upgrade it.

In Python

import pedigree_ga4gh as pg

doc = pg.load("/data/examples/okafor_ga4gh-pedigree.json")
findings = pg.validate(doc)
print(pg.render_findings(findings))
print("valid" if pg.is_valid(findings) else "not valid")
