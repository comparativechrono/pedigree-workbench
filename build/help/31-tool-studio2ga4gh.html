Drawing → GA4GH Pedigree and Phenopackets

studio2ga4gh turns a Pedigree Studio drawing into a GA4GH Pedigree and a Phenopackets Family. These are the files you use to share a family's pedigree and findings in the GA4GH standard.

The form

The drawing
Choose a Pedigree Studio file, or the drawing in the Studio tab.
Terms for its conditions
Choose a terms file that gives each condition in the colour key its ontology term (terms files). Under it, a table shows the term each condition will get. A condition that already has an id in the key, such as Condition X [MONDO:0009061], doesn't need a terms file. Only an ontology's id counts, so Hypertension (BP:160/95) is just a name. A condition without a term is left out, because a GA4GH file has no place for a condition without one. Match them to terms…, under the table, opens the tool that finds the missing terms.
People are named by
The default, and the safe choice, is pedigree numbers such as II-3. You can also choose the labels in the drawing, which are often names, or Pedigree Studio's own ids. A label becomes an id in the same way as in studio2ped (J. Mensah becomes J_Mensah, for example), so a person has the same id in both tools' files. If an id would be empty, 0 or the same as someone else's, the pedigree number is used instead, with a note.
Family id
The default, FAM, gives FAM1, then FAM2 and so on if the drawing holds more than one family.
Files to write
You can write both files, or just one of them.
Save in, Start of the file names
The files are called start_ga4gh-pedigree.json and start_phenopackets-family.json. They're saved in ~/results unless you choose another folder.

What goes into the files

In the drawingIn the GA4GH files
square, circle, diamondsex MALE, FEMALE, UNKNOWN_SEX
the slash through a deceased person's symbolvital status DECEASED (otherwise ALIVE)
the proband's arrowthe index patient, and the Family's proband
fill, halves, quarters, shadinga disease (Mondo) or phenotypic feature (HPO) for each condition named in the key, once it has a term
a child's line from a coupleisBiologicalMotherOf, isBiologicalFatherOf (isBiologicalParentOf when the parent's sex is unknown)
a dashed line of descentisAdoptiveParentOf
D or S in a parent's symbolisSpermDonorOf or isOvumDonorOf for D, and isGestationalCarrierOf for S (not a biological parent)
identical and non-identical twinsisMonozygoticMultipleBirthSiblingOf, isPolyzygoticMultipleBirthSiblingOf
consanguineous, separated and childless couplesisConsanguineousPartnerOf, isSeparatedPartnerOf, isPartnerOf
a pregnancy lossa person who is DECEASED, noted in the narrative
the no children and infertility barsnot written as people, but noted in the narrative
a carrier's dot, a presymptomatic line, Pnoted in the narrative, because there's no ontology term for them
names and notes under the symbolsnot written, because Phenopackets have no field for a name, and such notes are often personal data

Every Phenopacket has its own metaData. This lists a resource for each ontology its terms come from, with that ontology's release, taken from the terms file. The GA4GH Pedigree and Phenopackets describe the files in full.

Under the result

The tool tells you what it wrote. It also notes anything that didn't go in as drawn, such as a condition without a term, a symbol that stands for several people (written as one person) or a carrier. Read the notes before you send the files.

In the terminal

studio2ga4gh /data/examples/okafor.studio.json -t /data/examples/example-terms.json -d ~/results
Option
-t FILE, --terms FILEthe terms file
-d DIR, -o STARTthe folder, which is made if it doesn't exist, and the start of the file names. By default, the files go in the drawing's folder and start with the drawing's name.
--ids numbers|drawing|studiohow people are named
--family-id ID, --created-by TEXTthe family's id, and who made the files, for metaData.createdBy
--only pedigree|familywrite one of the two files

In Python

import json
from studio2ga4gh import convert_file

terms = json.load(open("/data/examples/example-terms.json"))
result = convert_file("/data/examples/okafor.studio.json", "okafor", "/home/user/results", terms=terms)
print(result.summary)
for note in result.warnings:
    print("note:", note)
