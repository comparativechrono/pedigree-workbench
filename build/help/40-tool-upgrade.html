Upgrade a file from an older tool

Earlier versions of our tools – studio2ga4gh up to 0.3, abusua2ga4gh up to 0.2 – wrote GA4GH files that the standard does not accept. The upgrade rewrites such a file, once, in the standard form, and lists every change it made and everything it could not do. It tidies other non-standard files too.

What it changes

  • The form: studio2ga4gh 0.3's GA4GH Pedigree, which was the conceptual model written out as JSON, becomes one Phenopacket per person, with relationships in the standard form.
  • What the standard has no place for: names are removed (Phenopackets have no field for a name, and names are personal data); diseases inside subject are moved to the Phenopacket; notes on relationships go into the narrative.
  • metaData: added where it is missing, with phenopacketSchemaVersion, and a resource for every ontology the terms use.
  • KIN: retired codes are replaced by the current ones, the people swapped where the new term runs the other way, and labels corrected; a relation whose code and label disagree is decided by its label (abusua2ga4gh's KIN:039 isSpermDonorOf becomes KIN:004).
  • Carriers: the phenotypic feature HP:0032500 written for a carrier is removed – it is Exacerbated by tobacco use – and a GA4GH Pedigree's narrative says who is a carrier.
  • Field names in proto spelling (index_patients) are written in camelCase (indexPatients), as JSON is.

What it leaves to you

Under to do, it lists what only a person can decide:

  • conditions with a name and no term: Fill in missing terms gives them their terms;
  • carriers in a Phenopacket or a Family: Phenopackets have no field for carrier status, and the only structured place for it is a genomic interpretation of the variant, if it is known (phenotk add --variant in the terminal: Add findings to people);
  • foster and social parents that abusua2ga4gh wrote as adoptive parents, which only the relationship's note tells apart;
  • for studio2ga4gh 0.3's GA4GH Pedigree, the conditions: it recorded who was affected, but not by what, so convert the drawing again or use the Phenopackets file made with it.

Nothing is guessed. A file that is already standard comes back as it was, apart from its field names. Under the result, Check the upgraded file runs the check on it.

In the terminal

pedigree-ga4gh upgrade /data/examples/older/abusua2ga4gh-0.2_phenopackets-family.json -o ~/results/abusua_phenopackets-family.json
pedigree-ga4gh validate ~/results/abusua_phenopackets-family.json

phenotk upgrade FILE -o OUT does the same.

In Python

import pedigree_ga4gh as pg

doc = pg.load("/data/examples/older/abusua2ga4gh-0.2_phenopackets-family.json")
new, changes, todo = pg.upgrade(doc)
pg.dump(new, "/home/user/results/abusua_phenopackets-family.json")
for c in changes:
    print("changed:", c)
for t in todo:
    print("to do:", t)
